This quickstart shows the fastest path to your first successful run using **Kubiya Web Composer**. No terminals, no SDKs, no prior integrations.

**Outcome:** you will create a minimal setup (hosted control plane, one agent, one team), run a task from plain English, watch it execute step-by-step, and save it as a reusable workflow.

**Time to complete:** \~5 minutes

## **Before you begin**

* Sign in to the Web Composer.
* In the top-left control-plane selector, keep **Kubiya Hosted – Managed**.

## **1\) Confirm the default environment**

Open **Environments** in the left navigation.

* You should see **Default Environment** in a **Ready** state.
* For this quickstart, leave everything as is. (Later, you can add environment variables, secrets, policies, tool sets, and context.)

## **2\) Create an agent**

Go to **Agents → Create Agent**.

* **Name:** for example, `Code Assistant`
* **Description:** Something simple like `“Help me out with coding and technical stuff”`
* **AI Model:** Use the recommended **Claude Sonnet 4**. No need to give your API key as all models are provided for free.
* **Capabilities:** Comma-separated tags describing what this agent can do. Like: `coding, monitoring`
* **MCP / Tools:** keep the defaults; the hosted control plane provides a working baseline

Save the agent.

## **3\) Create a team and add your agent**

Go to **Teams → Create Team**.

* Give a name to the team like `Assistant Squad`
* In the **Members** section, add the agent you just created.
* Save.
  Teams provide an execution boundary and inherit environment configuration and tools.

## **4\) Run your first task in the Composer**

Open **Task Kanban** and click **New Task**.

In the chat box, describe a simple goal, for example:

* “Create a simple HTTP server, start it, call it, and show the response.”
* “Fetch a web page and summarize the content.”
* “Check disk usage and print the top 5 largest directories.”

What happens behind the scenes:

1. The agent interprets your goal using the team/project context.
2. Kubiya plans safe steps and compiles them into a deterministic, containerized workflow.
3. Hosted workers execute each step in isolation.
4. You see real-time events, logs, and status for every step.

## **5\) Save it as a reusable workflow**

When the task completes successfully, click **Save as Workflow**.

* Give it a clear name and description.
* Choose who can run it (team or project).
* Save.
  The workflow now appears under **Workflows** and can be run on demand or scheduled.

## **What you used (and why it works)**

* **Hosted Control Plane:** central coordination with zero setup.
* **Agent:** understands goals and proposes safe, deterministic steps.
* **Team:** groups agents and inherits environment/tooling.
* **Hosted Workers:** execute steps in isolated containers with streaming logs.

This design ensures the same input follows the same execution path, with clear logs and isolation between steps.

## **Next steps**

When you’re ready to go beyond the quickstart:

* **Environments:** add variables, secrets, integration credentials, OPA policies, and **Tool Sets** to control what your workflows can do.
* **Task Workers:** create a queue and connect self-hosted workers when you need access to private networks or custom capacity.
* **Projects & Teams:** organize goals, context, and permissions as your usage scales.
* **Agents:** attach additional MCP servers or adjust capabilities as new use cases appear.

You now have a clean baseline and a working first workflow. From here, you can layer in security, context, and integrations at your own pace.
